# What works and what needs work

**Status: development preview.** The mod is playable, but it is not finished or production ready yet.

## Working

- Quest 3 headset/controller tracking through Steam Link and SteamVR.
- The general VR view, controller laser and main-menu experience.
- Floating menus and a HUD that follow your view.
- Readable settings controls, with controller clicking and scrolling.
- PC mode and tracked-avatar support for modded players.
- The Visual Studio project, build tools, setup/play guides, Git repository and MIT license.
- One setup command prepares dependencies, builds and creates a separate game copy with verified files and PC/VR launchers. A fresh current-version install passes end-to-end setup checks without changing the stock game.

## Changed, needs another headset check

- Empty-handed agents can request a native tackle with right grip + B, or right grip + lower right pad on Vive/original WMR. Simulated checks cover actual movement along headset heading, native animation/command/cooldown, stable view recovery, settings/focus suppression, input blockers and actual head obstruction. Held-item secondary, hip swap and ordinary scammer input remain native. Collision hit outcomes, remote presentation and headset comfort still need checking.

- Contraband storage now uses a held controller chord: left grip + left Y, or left grip + left menu on Vive/original WMR. Native charge/cancel, storing and retrieving a registered pepper-spray item, and preserving its partial-use state pass simulated checks. Input ownership prevents a cancelled hold from turning into settings or restarting after focus/tracking loss. Capacity limits, other item variants, multiplayer and headset usability still need checking.

- VR UI discovery now caches documents through their enable lifecycle and spreads presenter/material maintenance across frames. In one simulated office/settings profile, UI-update peaks fell from roughly 8 ms to about 3.6 ms and repeated global document searches stopped. Late document activation, button input and disable/re-enable pass core checks. This does not establish headset/GPU or busy multiplayer performance.
- The updated Steam game now passes simulated startup, pointer, computer/settings, grip, native NPC damage and rig checks with matching dependencies. Older game copies keep their separate dependency profile.

- Temporary controller capsules (the bean shapes) are removed. The laser now hides during idle gameplay and uses steadier UI aiming, a smaller distance-scaled reticle and more forgiving double clicks. Its feel still needs a headset check.
- Punch input now stops when grip is released, even if trigger stays down. Native unarmed firing, controller aim, cooldown rejection and nonlethal NPC damage have been checked. Knockback now uses controller direction too; PvP, knockouts and other weapons still need checking.
- Native punch direction and arm targeting now follow the right controller. Simulated checks cover nearest-hit targeting, camera fallback when tracking/focus is lost and controller direction in the native animation command. Remote appearance still needs two-account testing.
- Native shotgun/sniper pickup, charging, early release, settings/focus cancellation, controller-origin shots and cooldown rejection pass simulated checks. Shotgun spread uses the controller's up/right axes, including when aiming upward. Both weapons also hit a native shooting-target fixture through the normal authority/feedback path, accept one hit per shot and restore the target afterward. Player/NPC damage from these weapons, other weapons and headset handling still need checking.
- Native weapon firing also passes with no PC mouse registered in the game's input system. VR supplies a compatibility device when needed; simulated checks cover one-device ownership, inactive-VR guarding, cleanup/recovery and restoration of the original mouse objects.
- Pepper spray passes native pickup, controller-following spray origin/direction, held-trigger use, release, settings/focus cancellation, fresh-press recovery, authored duration/depletion and drop checks. Spray damage/effects against other players and headset presentation still need checking.
- Javelin targeting now follows the right controller for the locally held item. Simulated checks cover the selected surface, one native trigger launch, the target sent to the authority command, synchronized fired state and normal held-item release. Inactive VR, lost focus/tracking and another unheld item retain camera targeting. Missile flight, explosions, recoil feel and the multi-missile variant still need checking.
- Left trigger provides world interaction while holding items, separate from the pee modifier. Held-item trigger and secondary actions now use native callbacks, covering food/tool use that weapon-only input skipped. Curry consumption, networked poop/gassy effects and normal expiry work in simulation. Native jump-driven curry boost activation, agent hip swap, extra item-action release and nonfinal cone activation/cooldown also pass simulated checks; trajectories and final cone use still need checking.
- Beer, burrito, coffee, coffee mug, coke, margarita, patron, water bottle and wine pass simulated controller use, menu blocking, native effect activation, server removal of the consumed item and timed expiry. Checks use shorter effect durations. Coffee stacking reaches its native speed cap and expires normally. Controller-driven alcohol pass-out now queues native consumption before ragdoll drops the final drink; native ownership checks, recovery, head alignment and tracked-pose restoration pass simulated checks. Ordinary native pass-out requests keep their immediate path. Authored durations, other alcohol combinations and headset handling still need checking.
- CCTV capture rendering now includes the local head and immediately restores first-person visibility. Automatic security detection, wanted captions, monitor interaction and headset appearance still need checking. - The handheld polaroid passes simulated controller shutter, native network photo creation, rendered image pixels, controller-driven camera movement and selfie-mode switching. Its photo render now includes the local head without leaving it visible inside the headset. Menu suppression and render-scope cleanup/recovery also pass; headset handling and remote-player photo appearance still need checking.

Headset handling and remote appearance still need checking.

- Hideable backpack entry, occupied-bag movement through native force commands, controller HUD hints and native jump exit/recovery pass simulated checks. The view follows the bag camera or authored centre. Self-owned held/hip equipment and the occupied bag no longer trigger the head-collision blackout; an external obstruction still blocks and clears the view in the bag check. Other bag variants, other players carrying the bag and headset comfort still need checking.
- Pee input now stops when a menu or lost focus interrupts gameplay and waits for a fresh chord before restarting. Simulated checks cover native network state, release, settings/players/feedback and session cleanup. Headset handling and remote appearance still need checking.
- Jump input now requires a fresh press after settings, players, feedback, focus loss or session cleanup. Simulated checks cover actual native takeoff/release, cancelled holds, presses begun inside menus and exactly one event on fresh recovery. Foot-jump release now runs before flight climb input, preventing the old release from cancelling drone ascent. Headset feel still needs checking.
- Full stick/pad travel now drives native sprint, with an auto-sprint toggle in VR options. Simulated checks cover native hold/toggle modes, threshold hysteresis, movement directions, sprint blockers, settings/feedback/focus cancellation, cleanup and ordinary native input when disabled. The native motor moves farther with sprint for the same full-stick input. Fast-climb event delivery is included; headset comfort and other native movement modes still need checking.
- Extension ladders now receive native climb events from the VR stick. Simulated checks cover controller extension, native mount, upward movement/player height, reverse climb velocity, camera height, head-step/turn isolation, menu/focus suppression, fresh jump dismount, input recovery and HUD controls. Disabled/destroyed occupied ladders release native callbacks and simulation blockers; held climb waits for neutral before ground actions. Other ladder variants, occupied retraction, remote clients and headset comfort remain unverified.
- FPV controller launch, native movement/steering/climb, camera/pose handoffs, real obstacle crashes and abrupt aircraft-destruction recovery pass simulated host checks. Left-trigger climb leaves both thumbs free; A/pad-up remains available. Menus/focus pause input and require a fresh climb press afterward. Held flight controls wait for neutral before becoming ground movement/jump/snap-turn, with a HUD release prompt. Steering options and owned-aircraft menu-ray filtering are included. Headset comfort, remote clients and other aircraft variants still need checking.
- Tracking reads and UI scans do less repeated work, floating/native UI occlusion shares one physics query, destroyed menu graphics release their owned material entries, and detached app trees release their saved corner styles. Smooth performance in busy scenes still needs more work.
- Discovery of texture-backed world panels now spreads renderer checks across frames, keeps active document targets together per batch, and drops unfinished scans on scene changes or shutdown. Mock profiling showed smaller individual discovery spikes with a small average CPU-cost increase; overall frame times were essentially unchanged. This is a hitch-reduction change, not a smooth-performance or headset frame-rate guarantee.

- Computer screens now stay attached to their desk monitors and follow screen movement and renderer rebinding. An optional floating desktop is available. Clicking, dragging, scrolling and window controls have been checked, but the revised computer experience still needs headset testing.
- A locally rendered browser page passes controller clicking, dragging, off-page release, thumbstick scrolling, focus cancellation, context-click and close-during-drag checks. Closing or hiding a pressed control now cancels its controller press. Live websites, text entry and headset usability still need testing.
- The browser gets more startup time under VR load. New game-copy installs start with a fresh browser cache.
- Paint passes simulated controller drawing, saved-image, undo/redo, held right-B brush resizing, HSV colour selection and focus-cancellation checks. - Eighteen native scam-app windows pass controller window controls. Four enabled forms also pass controller focus, scrolling to clipped controls and empty-submit validation. Native notification dismissal works. Successful completion across the remaining apps and dialogue-specific controls still need checking.

## Not finished

- Every computer app and every action inside those apps.
- Combat damage against players, charged/ranged hit outcomes and remaining weapons, other food variants, boost trajectories/final cone use and all held-item variants in VR.
- Headset combat feel and player-versus-player reliability still need checking. Controller attacks are rejected while the head is inside world geometry.
- Complete multiplayer checks across separate Steam accounts, including reconnecting and joining late.
- Consistently smooth performance, especially in busy scenes.
- Violent ragdoll/final cone impacts, completed give-up outcomes, hiding variants, spectating, tracking loss and every seated/standing transition.
- Headset/controller compatibility beyond the setup already tried.
- Hardware verification of the new Vive wand/original WMR alternate controls, including runtime-reported controller names, touchpad behaviour and menu availability.
- Headset acceptance of the updated Steam game using Unity 6000.3.26f1 and Input System 1.20.0.

## Not included right now

- Grabbing the desk mouse or touch typing on the desk keyboard. That experiment was removed.
- A VR keyboard by default. Use a physical PC keyboard for text entry; the optional floating keyboard remains experimental and disabled.
- A standalone Quest app or an IL2CPP version.
- The separate general game optimization mod. That comes after the VR mod is finished.
